# Control how tasks are added to projects

This article presents a practical approach for controlling how tasks are added to projects. This can be a key step in managing and protecting an [established workflow](https://help.asana.com/s/article/what-is-a-workflow?language=en_US). Since adding a task often triggers crucial workflow [rules](https://help.asana.com/s/article/rules?language=en_US), it's vital to prevent these rules from being accidentally activated by incomplete or unintended tasks.

To minimize this risk, employ a strategic mix of project permission settings and forms, designed to collect information from the right people in the right way.

First, we'll adjust the project's permission settings to allow only a select few people to edit the project details, including tasks. This step ensures that others cannot add tasks to the project. Then, we'll introduce a form to sidestep this limitation, permitting the addition of tasks only if they include all the necessary information required for the workflow. This can be an important step in [assigning work automatically with custom fields](https://help.asana.com/s/article/assign-work-automatically-with-custom-fields?language=en_US).

## Set project access settings to viewer or commenter

The first step involves changing permission settings, both the default project permissions as well as permissions settings for [individual project members](https://help.asana.com/s/article/individual-project-permissions?language=en_US).

1.  Click **Share** in the top-right of the project.
2.  Under **Access settings**, change the default settings for the organization and/or team to **viewer** or **commenter**. This still allows others to view the project's contents, depending on project privacy, without editing or adding any tasks.
3.  Set individual member permissions to the appropriate level, based on the actions the members need to take within the project.

The result is that now, only those who need access to edit project details may do so. Everyone else is restricted from editing any part of the project. Temporarily, they cannot add tasks to the project in any way. Adding a form to the project will allow those without edit access to add tasks to the project via form submissions only, which can be tailored so that they capture all the relevant information before any work begins, or any workflow is triggered.

## Use a form to overcome access restrictions and add tasks

The first step of controlling how tasks are added to the project involved restricting edit permissions to a select group of members. The next move is to enable a controlled method for others to contribute tasks without granting them edit rights, thus preserving the integrity of the workflow.

To do this, [create a form](https://help.asana.com/s/article/forms?language=en_US) in the project:

1.  Navigate to the **Customize** menu in the right corner of your project.
2.  Scroll down to **Forms** and click **+ Add form.**
3.  Write your form questions to gather essential information.
4.  Optionally, make questions mandatory to ensure submissions trigger your workflow.
5.  Share the form link via task, email, or message.

The result is that organization members and guests who previously could not add a task to the project due to their **commenter** or **viewer** permissions, can now add tasks in a controlled way via the form.

This method can be used as a starting point for many workflows which involve the addition of a task to a project, where existing tasks and workflow components must remain undisturbed.
