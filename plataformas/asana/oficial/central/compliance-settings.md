# Asana compliance settings

This article explains how HIPAA and AsanaGov compliance settings work together when both apply to the same domain. When two requirements differ, Asana uses the stricter setting. When they match, Asana keeps the shared setting and reflects the combined compliance requirements in the admin experience.

## What changes when HIPAA and AsanaGov overlap

On domains that use both HIPAA and AsanaGov controls, Asana applies the stricter setting for any compliance-sensitive option. That helps keep domain settings aligned with the most restrictive requirement without asking admins to manage separate rules in two places.

If both compliance programs use the same value, Asana keeps that setting in place. The banner in the product should point users to this article when they need more detail about why a setting is restricted.
